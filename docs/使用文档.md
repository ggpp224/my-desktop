## 1. 环境准备

### 1.1 必需环境

| 项目 | 要求 |
|------|------|
| Node.js | 18.x 或 20.x（LTS），建议使用 nvm 或官方安装包 |
| Ollama | 已安装并拉取模型，推荐 [Ollama 官网](https://ollama.com) 安装 |
| 系统 | macOS（优先）、Windows（Browser 工具会使用 `start` 打开链接） |

### 1.2 安装 Ollama 与模型

```bash
# 安装 Ollama 后，先拉取知识库必需模型
# 1) 向量嵌入（必需）
ollama pull bge-m3

# 2) 知识库问答（默认）
ollama pull qwen2.5:7b

# 3) 知识库预处理（推荐）
ollama pull qwen2.5-coder:14b

# 4) 通用本地对话（可选）
ollama pull qwen2.5

# 确保服务运行（可选，部分安装方式会自动启动）
ollama serve
# 或交互式运行
ollama run qwen2.5
```

> 若你开启 `KB_RERANK_MODE=model`，请确认 `KB_RERANK_MODEL` 对应模型在本机可用；不可用时建议先回退 `KB_RERANK_MODE=rule`。

### 1.3 一键自检知识库模型

```bash
# AI 生成 By Peng.Guo
required_models=("bge-m3" "qwen2.5:7b" "qwen2.5-coder:14b")
installed="$(ollama list | awk 'NR>1 {print $1}')"
missing=()
for model in "${required_models[@]}"; do
  echo "$installed" | rg -q "^${model}$" || missing+=("$model")
done
if [ ${#missing[@]} -eq 0 ]; then
  echo "知识库模型检查通过：全部已安装"
else
  echo "缺少模型：${missing[*]}"
  echo "请执行："
  for model in "${missing[@]}"; do
    echo "  ollama pull ${model}"
  done
fi
```

## 2. 安装与启动

### 2.1 安装依赖

在项目根目录（my-desktop）执行：

```bash
npm install
```

会自动执行 `postinstall`，在 `ui/` 下安装前端依赖。

### 2.2 验证 Ollama Tool Calling（可选）

确认本机 Ollama 支持 tool calling 及返回格式：

```bash
npm run verify-ollama
```

需先启动 Ollama。若输出包含 `OK: Ollama returned structured tool_calls` 表示验证通过。

### 2.3 开发模式

一键启动前端、后端与 Electron 窗口：

```bash
npm run dev
```

脚本会先执行 `tsc` 编译，再同时启动：

- Vite 开发服务器（UI）：<http://localhost:5173>
- Electron 窗口（加载 5173）；**API 以子进程自动拉起**（默认 <http://localhost:41738>，见 `.env` 的 `API_PORT`），与 Electron 主进程隔离，避免原生模块导致崩溃
- 启动前若 API 端口已有残留进程会先终止再启动；**退出应用时自动结束 API 子进程**

若希望分终端分别启动，可执行：

```bash
# 终端 1
npm run dev:ui

# 终端 2（可选：仅调试 API，不经过 Electron）
npm run dev:server

# 终端 3（需先执行一次 tsc）
npx tsc
npm run dev:electron
```

注意：同时跑 `dev:server` 与 `dev:electron` 会争用同一 `PORT`；Electron 启动时会先释放该端口再启动 API。

**勿在 `.env` 使用 `PORT`**：`cc-web` 的 `cjet dev` 会读 `process.env.PORT`。本应用请只用 `API_PORT`（默认 41738），否则「开始工作」里的 cc-web 会与 API 抢同一端口，API 被 SIGKILL。

### 2.4 生产构建与运行

```bash
npm run build
npm run start
```

- `npm run build`：编译 TypeScript 并构建 UI 到 `ui/dist`。
- `npm run start`：启动 Electron；主进程会先释放配置端口（默认 41738）再启动 Express，退出时自动关闭 API，并加载打包后的 UI（不再依赖 5173 端口）。

## 4. 界面使用

顶部 **Header 页签**：`AI Dev Control Center`（主工作区）与 `技术趋势` 并列常驻；后者不可关闭，切换时保持刷新 SSE 不中断。

### 4.1 Chat 面板

- **输入框**：输入自然语言指令，如「开始工作」「启动 react18」「启动 mdf-ui」「启动 base」「打开 Jenkins」「部署 nova」「合并nova并部署相关服务」「ws打开base」「关闭cursor的scm」。完整指令见 [可用指令](./可用指令.md)。
- **快捷按钮**：点击「开始工作」「打开 Jenkins」等会直接发送对应文案到 Agent；项目列表来自 `config/projects`，含 **mdf-ui**、**mdf-biz** 等，可点「启动 xxx」快捷启动（xxx 为项目代号）。
- **右上角帮助（?）**：展开可用指令说明、项目代号速查及启动命令（默认 `yarn dev`，mdf-ui/mdf-biz 为 `yarn w`）。
- **指令路由**：固定口令（如「打开json配置中心」「开始工作」）与「部署/合并/启动」等模式口令由系统确定性解析并**直接执行**，不经过首轮 LLM，也不会误进知识库问答；仅自然语言说明类问题才走 `query_knowledge_base`。Logs 中可查看 `[intent]` 行确认路由结果。
- **消息区**：展示用户与 AI 的对话，以及本次调用的工具结果（若有）。
- **流式返回**：聊天默认使用 `/agent/chat/stream`，可实时看到模型增量输出、工具执行进度与 token 统计；异常时自动回退普通请求。
- **指令统计**：发送「统计常用指令」或经 Agent 打开「指令统计」页签，可查看柱状图、饼图、折线图（默认最近 30 天，可选 7/30/90 天或自定义区间）；数据来自本机 SQLite `runtime/command-stats.sqlite`。
- **知识库问答**：当你输入「某组件怎么用」「文档里如何配置」这类问题时，系统会自动调用本地知识库（默认 `runtime/private-kb/**/*.md`）返回答案，并附带引用片段来源。
- **知识库持久化**：索引会持久化到本地 `runtime/knowledge-index`。服务重启后优先加载本地索引；仅当文档有变更时才重建索引。
- **模型模式切换**：右上角支持「本地 / 外部」切换。本地模式使用 Ollama；外部模式使用 Gemini（可在设置中填写 API Key/模型/Base URL）。
- **主题切换**：右上角 `ThemeSwitcher` 支持多主题切换，选择会写入本地存储，重启后保持。

### 4.1.1 模型设置（Gemini）

- 点击右上角「⚙ 设置」可打开模型设置弹窗。
- 外部模式下可配置：
  - `Gemini API Key`
  - `模型 ID`（默认 `gemini-2.0-flash`）
  - `API 根地址`（可选）
- 点击「连接测试」会调用 `POST /agent/gemini/test` 验证连通性（不落盘）。
- 点击「保存」后仅写入前端本地存储；请求时通过 `body.llm` 传给后端，服务端不写文件。

### 4.2 Workflow 面板

- 列出当前支持的工作流（如 `start-work`）。
- 点击某一工作流名称即可发送「执行工作流 xxx」类指令，由 Agent 调用 workflow 工具执行对应 JSON 配置。
- 对于「开始工作」等场景，支持启动内嵌终端会话：UI 会新增「终端」页签，展示多终端输出并支持实时交互。

### 4.3 Tool 面板

- 展示当前可用的工具名称与简要说明：run_workflow、run_workflow_step（含工作流外项目启动）、deploy_jenkins、merge_repo、composite_nova_merge_and_deploy、open_in_ide、close_ide_project、open_browser、run_shell。

### 4.3.1 单独启动某个项目

- **工作流外**（仅在 `config/projects` 配置路径）：如「启动 base」「启动 nova」「启动 mdf-ui」「启动 mdf-biz」——在系统终端进入项目目录执行开发命令；多数为 `yarn dev`，**mdf-ui / mdf-biz 为 `yarn w`**。

- 显示请求与执行的简要日志（如「发送: …」「Agent 完成」），便于排查问题。

### 4.5 私人知识库页签

- 可通过自然语言「添加私人知识库」或点击相关入口打开「私人知识库」页签。
- 支持选择本地目录并导入其中的 Markdown 文档（调用 `POST /knowledge-base/import`）。
- 导入后可直接触发增量/全量索引重建。
- 在回答引用来源中点击文档，可打开独立文档页签（`KnowledgeDocPanel`），并支持 Markdown 内相对链接跳转。

### 4.6 技术趋势页签

- 点击顶部 **「技术趋势」** 页签进入（与「AI Dev Control Center」并列的常驻页签）。
- **今日**：GitHub 日榜 + HN + Reddit 日榜 → 关键词过滤（Agent/MCP/IDE/LLM 等）→ 本地 Ollama 或外部 Gemini 生成 Markdown 解读。
- **中长周期**：一键顺序刷新「本月」「半年度」两份报告（GitHub 月榜 + Reddit 月/年榜）；HN 仅参与今日抓取。
- 右上角 **刷新** 通过 `POST /tech-digest/refresh/stream`（SSE）推送抓取进度与 LLM 增量；**取消** 可中止当前 scope 的刷新。
- 页签常驻挂载：切换到其它页签不会销毁面板，进行中的 SSE 不会中断。
- 缓存与历史：
  - `runtime/tech-digest/latest-daily.json`、`latest-monthly.json`、`latest-halfyear.json`
  - `runtime/tech-digest/history.sqlite`：记录每日 Top10 项目，用于「近 7 天上榜频次」
- 出站 HTTP 抓取复用 Gemini 同款代理（`HTTPS_PROXY` / SOCKS / macOS 系统 SOCKS）；Reddit 默认串行限流，完整刷新需数分钟。
- 详细操作与配置见 [可用指令 - 技术趋势](./可用指令.md#技术趋势)。

### 4.7 MD 生成 PDF 页签

- 通过输入 **`md生成pdf`**（或工具入口）打开「MD 生成 PDF」页签。
- 支持两种选文件方式：`选择 MD 文件`（Electron 原生对话框）与 `上传 MD`（浏览器文件选择）。
- 点击「生成」后，会在源文件同目录输出同名 `.pdf`（例如 `a/b/readme.md -> a/b/readme.pdf`）。
- 版式采用 GitLab/GitHub Markdown 风格，支持表格、代码高亮。
- 代码块中的 Mermaid（如 ```` ```mermaid ````、`flowchart`、`subgraph`）会在导出前渲染成 SVG 后再打印到 PDF。
- 该能力依赖 Electron 写文件；若是纯浏览器预览模式会提示“仅支持 Electron 桌面端”。

## 5. 工作流配置

工作流为 JSON 文件，放在项目根目录的 `workflows/` 下，例如 `workflows/start-work.json`：

```json
{
  "steps": [
    { "tool": "shell", "cmd": "docker compose up -d" },
    { "tool": "browser", "url": "https://github.com" },
    { "tool": "browser", "url": "http://localhost:8080" }
  ]
}
```

- **tool**：`shell` | `browser` | `jenkins`。
- **shell** 步骤需带 `cmd`；**browser** 需带 `url`；**jenkins** 需带 `jobName`。
- 执行顺序与 steps 数组一致；任一步失败则中止并返回错误信息。

修改或新增 JSON 后，无需重启应用即可在 Workflow 面板或通过自然语言「执行工作流 xxx」调用（工作流名称为文件名不含 `.json`）。

## 6. 知识库专项说明（重点）

### 6.1 数据来源与导入

- 系统会从 `KB_DOC_DIRS` 指定目录读取 Markdown 文档（默认 `doc,docs,runtime/private-kb`）。
- 通过 `POST /knowledge-base/import` 导入私人知识库后，文档默认写入 `runtime/private-kb/import-latest`。
- 再次导入同一来源时会先清理旧目录，避免旧文件残留造成检索噪音。

### 6.2 重建与增量重建的区别

- **重建知识库索引**：全量重建（所有文档重做预处理 + 向量索引）。
- **增量重建知识库索引**：按文档指纹做增量预处理（未变化文档复用缓存），再构建新索引快照。
- UI 反馈会区分：
  - 历史已缓存
  - 本次已处理
  - 本次复用
  - 当前处理中

### 6.3 查询与排序策略

- 采用 Hybrid Search：向量检索 + 关键词检索融合。
- `KB_HYBRID_ALPHA` 控制融合权重：
  - `0`：全关键词
  - `1`：全向量
  - 默认 `0.4`（关键词权重更高）
- 重排策略：
  - `rule`：规则重排（本地稳定，默认）
  - `model`：本地模型重排（需对应 rerank/chat 能力）

### 6.4 常见问题排查

- **重启后提示文档变化，查询失败**
  - 优先确认 `KB_PERSIST_DIR` 未变更、文档目录未漂移。
  - 执行一次“重建知识库索引”刷新快照。
- **引用来源明显偏题**
  - 先看 `KB_HYBRID_ALPHA` 是否过高偏向向量或关键词。
  - 再看重排模式是否合适（优先 `rule`）。
- **关键规则补充疑似被截断**
  - 开启 `KB_RULE_PATCH_DEBUG=1`，查看候选、入选、missing 判定日志。

## 8. 常见问题

**Q：界面提示「请先安装并启动 Ollama」？**  
A：表示 `/health` 检测到 Ollama 不可用。请确认 Ollama 已安装、已启动（如 `ollama serve`），且已拉取模型（如 `ollama pull qwen2.5`）。

**Q：说「部署 xxx」没反应或报错？**  
A：需配置 `JENKINS_BASE_URL` 和（如需要）`JENKINS_TOKEN`，并确保 Jenkins 可访问。未配置时工具会返回「Jenkins 未配置」类提示。

**Q：Shell 命令在错误目录执行？**  
A：通过环境变量 `SHELL_CWD` 指定工作目录，默认为启动应用时的当前工作目录。

**Q：如何只跑后端 API 做联调？**  
A：开发时执行 `npm run dev`，API 随 Electron 自动启停。仅调试后端可执行 `npm run dev:server`（或 `tsx watch server/api.ts`）；前端可单独 `npm run dev:ui`，通过 `electronAPI.getApiBase()` 或 `VITE_API_URL` 指向 API。

**Q：外部模型提示连接失败（Gemini timeout）怎么办？**  
A：优先检查本机网络连通。可在启动后端前设置 `HTTPS_PROXY`（如 `http://127.0.0.1:7890`）并重启；或在设置中填写可访问的 API 根地址。仍失败可调大 `GEMINI_CONNECT_TIMEOUT_MS`。

**Q：「开始工作」里的「打开终端」是打开网页吗？**  
A：不是。会打开本机的 **系统终端（macOS 的 Terminal.app）** 窗口或新页签，并在其中执行命令（如 `cpxy`）。已有终端窗口时会模拟 **Command+T** 新建一个页签再执行。若 macOS 上终端没有弹出或未在新页签执行，请到 **系统设置 → 隐私与安全性 → 自动化** 中允许本应用控制 **Terminal** 和 **System Events**。

**Q：我的工作页签（内嵌终端）关闭后还能恢复吗？**  
A：会话 ID 会暂存到浏览器本地存储。应用聚焦或刷新时会尝试自动恢复；若后端会话已失效会自动清理本地记录。

**Q：`md生成pdf` 导出失败常见原因有哪些？**  
A：常见原因包括：选择的不是 `.md` 文件、当前运行在浏览器预览模式（非 Electron）、Markdown 中 Mermaid 语法错误或渲染超时。优先在 Electron 中重试，并检查 Mermaid 代码块语法。

**Q：技术趋势刷新很慢或 Reddit 报错？**  
A：Reddit 对匿名/RSS 抓取有严格限流。默认串行间隔 8s，遇 429 冷却 45s；「中长周期」需抓取 6 次 Reddit，整体约 2–3 分钟属正常。可配置 `REDDIT_CLIENT_ID` + `REDDIT_CLIENT_SECRET` 走 OAuth；或调大 `TECH_DIGEST_REDDIT_GAP_MS`。出站请求需能访问 GitHub/HN/Reddit（可配 `HTTPS_PROXY`）。

**Q：技术趋势报告为空或 LLM 超时？**  
A：确认 Ollama 已启动且模型可用（或外部 Gemini 连通）；可调大 `TECH_DIGEST_LLM_TIMEOUT_MS`。若某数据源抓取失败，报告顶部会显示「数据源提示」，其余源仍会参与分析。
