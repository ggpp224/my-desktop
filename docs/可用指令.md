| 操作 | 说明 |

| **今日** 子页签 + 刷新 | 独立抓取 **GitHub Trending（日榜）**、**Hacker News Top**、**Reddit r/LocalLLaMA / r/OpenAI（日榜）**，经关键词过滤与 LLM 分析后生成 Markdown 报告；缓存于 `runtime/tech-digest/latest-daily.json`。 |
| **中长周期** 子页签 + 刷新 | 顺序刷新 **本月** 与 **半年度**（各独立抓取与分析）：GitHub 月榜 + Reddit 月榜/年榜；缓解 Reddit 限流。缓存分别为 `latest-monthly.json`、`latest-halfyear.json`。 |

**报告内容（今日）：** Top 项目解读、值得深挖 Top5、热度 Top20、本周技术趋势、近 7 天上榜频次（依赖 `history.sqlite` 累积）。

**报告内容（中长周期）：** 关注榜 / 源码研读榜 / 热度榜 Top20，以及周期技术趋势摘要。

**模型与网络：**

- 默认使用当前 **本地 Ollama** 或右上角 **外部 Gemini**（与 Chat 同源 `body.llm`）；temperature 由 `OLLAMA_TECH_DIGEST_TEMPERATURE` 控制（默认 `0.3`）。
- 出站抓取走与 Gemini 相同的代理策略（`HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY` / macOS 系统 SOCKS）。
- 可选：`GITHUB_TOKEN` 提升 GitHub 元数据质量；`REDDIT_CLIENT_ID` + `REDDIT_CLIENT_SECRET` 走 OAuth API；`REDDIT_USER_AGENT` 自定义 UA（Reddit 要求唯一标识）。

**限流与耗时：**

- Reddit 请求串行，默认间隔 `TECH_DIGEST_REDDIT_GAP_MS`（8s）；遇 429 全局冷却 `TECH_DIGEST_REDDIT_429_COOLDOWN_MS`（45s）。单次「中长周期」刷新约 2–3 分钟量级。
- LLM 分析默认超时 `TECH_DIGEST_LLM_TIMEOUT_MS`（10 分钟）；刷新中可点取消中止当前 scope。

**周报指令补充说明：**

**知识库指令补充说明：**

- 增量重建并不等于“完全不动索引文件”，而是“预处理增量 + 索引快照重建”。
- 重建过程反馈区会显示：历史缓存、本次已处理、本次复用、处理中。
- 若查询提示文档变化，可先执行一次重建；若仅重启后出现，优先检查索引目录和文档目录是否变化。

- **鉴权配置**
  - 必填：`WIKI_TOKEN`（未配置时会报错，避免误走匿名或错误结果）。
  - 可选：`WIKI_AUTH_SCHEME`（默认 `Bearer`；若公司网关要求可改为 `Token`）。
- **目标空间配置**
  - `WIKI_BASE_URL`：Wiki 域名（默认 `https://wiki2.rd.chanjet.com`）。
  - `WIKI_WEEKLY_SPACE_NAME`：周报空间名（默认 `低代码单据前端空间`）。
  - `WIKI_WEEKLY_ROOT_PAGE_ID`：周报根节点页面 ID（默认 `405143687`）。
- **定位算法（API 优先）**
  - 先从根节点开始，逐层拉取 `child/page`（兼容不支持 `descendant/page` 的 Confluence 实例）。
  - 在真实目录节点里按**当前日历季度**（`JIRA_WEEKLY_REPORT_TZ` 时区，默认上海）选季度页（标题匹配 `YYYY-QN`）；若 wiki 已提前建好未来季度页，不会误选编号更大的季度。
  - 再在该季度下按**本周一～本周日**（`yymmdd-yymmdd`，与 Jira 业务周一致）精确匹配周页；若尚未创建则回退到本周一之前已结束的最新周。
  - 搜索回退关键词亦使用上述周区间标题，而非当天日期。
- **回退策略**
  - 若 API 查询失败或未命中周页，自动回退到 wiki 搜索结果页，便于人工确认与跳转。
- **返回结果字段**
  - `quarter`：命中的季度标题（如 `2026-Q2`）。
  - `weekRange`：命中的周区间标题（如 `260413-260419`）。
  - `targetUrl`：最终打开 URL（命中时为周报页；回退时为搜索页）。
  - `matchMode`：`api_descendants`（API 命中）或 `search_fallback`（搜索回退）。

- 未配置时，执行 `cursor用量` 会自动尝试同步本机 Chrome 登录态 Cookie。
- 可选覆盖接口地址：`CURSOR_USAGE_API_URL`。
- 请求方式为 `POST`，请求体包含：
  - `teamId`（默认 `-1`，可用 `CURSOR_TEAM_ID` 覆盖）
  - `startDate`（按每月固定锚点时间计算；锚点可用 `CURSOR_USAGE_MONTHLY_BASE_START` 配置，默认 `1774764813000`）
- 请求会携带来源校验头（默认）：
  - `Origin=https://cursor.com`
  - `Referer=https://cursor.com/dashboard`
  - 如需覆盖，可配置 `CURSOR_API_ORIGIN`、`CURSOR_API_REFERER`
